The existing implementation provides a good security baseline, but it does not yet have a passage-level retrieval benchmark or version-complete answer provenance.

- `backend/app/repositories/support_knowledge.py:37` already defines a provider-independent `SupportKnowledge` port. Reuse it rather than introduce a parallel retrieval system.

- `backend/app/ai/providers/bounded_support.py:29–65` bounds reference context and permits only selected identifiers from the retrieved set. `backend/app/services/support.py:69–100` rechecks source availability/retrieval after provider work and reconstructs exact quotations from trusted passages. Those guarantees establish citation integrity; they do not establish that a selected quotation answers the question.
- `backend/app/support/knowledge.py:62–109` loads only the fixed corpus file and checks review, document digests and expiry. An issue anywhere in the deployed package makes the package unavailable. No arbitrary ingestion occurs.

Important gaps:

1. **Approved-version traceability is incomplete.** `SupportMatch` at `backend/app/schemas/support.py:79` and `SupportReference` at `:121` omit source revision and document digest. The package retains those fields, but retrieval strips them. A response identifies the current public source/passage and quote, not an immutable historical approved version.
2. **Knowledge management is manual.** There is no authoritative ingest → parse → normalize → chunk → validate → review → approve → publish/version/remove workflow. Do not mistake the existing typed JSON and readiness helper for that full lifecycle.
3. **Review diagnostics are discarded.** `knowledge.py:80–102` catches failures and returns empty knowledge. Safe diagnostic codes already exist in `services/support_readiness.py:76–115`; the deployed wrapper does not retain them for observability.
4. **Conflict handling is declarative, not semantic.** The readiness helper supports `declared_conflict`, but the deployed `CorpusDocument`/package schema does not expose per-document conflict flags; all constructed reviews use the default false. No semantic contradiction detection exists.
5. **Permissions currently mean approved public documentation.** This is appropriate for the pilot. There is no source-specific authenticated audience/tenant ACL. Future semantic retrieval must not silently broaden the corpus.

For the proposed reproducible benchmark:

- Pin dataset version, corpus revision, canonical document digests, evaluation timestamp and retriever version.
- Give every case a stable ID, intent-family ID, category, public question, expected outcome (`answerable`, semantic abstention, or corpus unavailable), approved relevant passage IDs, alternative equivalent passages, required evidence groups for multi-part questions, forbidden references, and reviewer rationale.
- Cover all 19 passages with exact and natural paraphrase questions, then add conceptual, multi-part, multi-passage, ambiguous, outside-corpus, stale-version, injection and unsupported-policy/action cases. Roughly 80–100 reviewed cases would be a reasonable initial proposal, not an imposed product requirement.
- Split by intent family so paraphrases do not leak across development and held-out evaluation. Freeze a held-out set before ranking changes.
- Keep source-state failures separate from semantic unanswerability. An expired corpus must produce unavailable; a broken provider must not receive credit for correct semantic abstention.
- Use deterministic mock selections to evaluate validation and citation reconstruction. Label this as contract performance, not LLM reasoning quality. Human-reviewed passage gold can evaluate selected evidence relevance without grading prose fluency.

Metric definitions should be explicit:

- Passage Recall@k: relevant retrieved passages divided by gold relevant passages.
- Precision@k: relevant retrieved passages divided by `k`; separately report precision over returned items when fewer than `k` are returned.
- MRR@k: reciprocal rank of the first relevant passage, averaged over answerable cases; misses score zero.
- Multi-part evidence coverage: required evidence groups represented, plus all-groups-covered rate.
- Structural citation accuracy: valid selected IDs, exact approved version/digest and exact quotation.
- Gold-relevant citation precision: selected references relevant to the reviewed question.
- Answer-support accuracy: answered cases whose cited evidence covers all required groups without forbidden/unsupported claims.
- Abstention accuracy and false abstention rate: report separately for unanswerable and answerable cases.
- Unsupported-answer rate: report both unsupported answers/all answered cases and false answers/all expected-abstention cases.
- Report availability failures, attempted answers and sample counts separately; never treat undefined denominators as perfect scores.

Recommended order:

1. Preserve lexical behavior and capture the frozen passage-level baseline.
2. Add internal immutable source-version/digest provenance and safe corpus-readiness diagnostics.
3. Define a reviewed, atomic publication manifest and lifecycle state machine; keep arbitrary ingestion and management HTTP APIs out.
4. Compare lightweight lexical improvements on development data, then the held-out set.
5. Decide whether the remaining paraphrase failures justify a semantic experiment.
6. Only after explicit embedding architecture/cost approval, add an optional semantic adapter and hybrid ranker behind the existing approved-source boundary.
7. Require authoritative approval/version/freshness filters before ranking; stale or unavailable approval metadata must fail closed. A semantic outage may fall back only to the fresh approved lexical snapshot.
8. Coordinate any public provenance fields with Sohaib before altering response schemas.

The current evidence justifies a better benchmark and semantic design exploration. It does **not** justify selecting an embedding provider, adding pgvector, migrating SQLite, or claiming that hybrid retrieval is already necessary.
